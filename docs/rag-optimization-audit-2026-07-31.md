# Ragent 优化审计（2026-07-31）

本文按“已经完成、这次补齐、需要独立改造、暂不实施”记录项目优化状态，避免把旧设想、历史评测结论和当前代码混为一谈。

## 一、此前已经完成

1. 小意图树直接 LLM 精判，大意图树才启用规则 / BM25 / 向量候选海选；避免在 10～20 个叶子场景继续使用 Top80。
2. 将资料类型意图与具体实体分离，由意图、实体和业务维度共同生成 `RetrievalPlan`。
3. Milvus 与 Elasticsearch 执行同一份分层元数据计划；唯一实体或明确元素命中即停止，未命中再逐层放宽。
4. 多通道候选按 Chunk 去重，超大候选池才用 RRF 限流，随后复用现有 Rerank 输出 TopN。
5. 原神 v7 与数码商品库使用独立知识库、实体目录、规则文件和 collection；顶层路由先确定语料范围。
6. 已有 SSE 首包探测与模型故障转移、AOP + TTL Pipeline Trace、Redis 分布式排队流控。
7. 已建立原神元数据检索 Gold A/B：56 题、Hit@5、MRR@10、Recall@20、集合覆盖率、Top5 无关结果和 P95。

## 二、本次补齐

### 1. 查询归一化幂等

修复同义词目标已存在时仍重复替换的问题，例如“元素战技”不再变成“元素元素战技”；增加重复执行、空映射等回归测试。

### 2. 高频别名数据治理

将高频俗称作为受控构建配置维护，补充“草神 → 纳西妲”，避免直接手改生成产物后在下次重建中丢失；增加实体解析回归测试。

### 3. 顶层路由安全性

- LLM 只有返回精确 Profile ID 才能路由，解释性文本中偶然出现 ID 不再误判；
- 显式 `UNKNOWN` 不再进入受管原神/商品库，LLM 调用失败则保留旧链路，避免外部模型故障影响公司知识库；
- “参数、型号、接口、技能、流程、状态”等通用词不能单独触发确定性路由，具体商品实体和强业务词仍可快速路由。

### 4. 构建编码固定

Maven 工程显式固定 UTF-8，消除 Windows 平台默认 GBK 导致资源复制口径不确定的问题。

### 5. 商品数据完整性校验

新增离线校验器，检查 7,532 个 Chunk 的逻辑键、哈希、长度、必需元数据、实体引用、类目、语言、Manifest 统计和意图规则；不调用模型、数据库或搜索服务。

### 6. 文档与代码状态同步

商品库说明和元数据契约已更新为当前事实：顶层路由、实体识别、检索 Plan 与分层召回已经接入；当前缺口是正式 Gold 评测，而不是运行时代码未实现。

## 三、验证结果

- 原神 v7 数据校验：6,562 个文档、7,742 个 Chunk、17 个语义节点，通过；
- 数码商品数据校验：1,108 个实体、7,532 个 Chunk，内部一致性通过；
- Java 聚焦回归：22 个测试全部通过；
- 编译仅保留项目原有的 ES 过时 API 与 unchecked 警告，本次未新增编译错误。

## 四、不能在本轮假装完成的事项

### 1. 检索后证据门控与引用

当前 `RetrievedChunk.score` 可能来自 Milvus、Elasticsearch 或 Rerank；候选数不超过 TopN 时还可能跳过 Rerank，因此不能直接设一个固定阈值。完整方案需要统一分数口径、保存来源与逻辑 Chunk Key，再建设拒答准确率和引用正确率评测。

### 2. 历史正文乱码重建

少量旧导入正文出现乱码，元数据仍可用于评测映射。修复需要先定位旧批次、备份，再重建 MySQL / ES / Milvus 对应数据，不能无备份覆盖。

### 3. Contextual Retrieval

当前 Chunk 已带标题、章节和结构化身份上下文，但尚未实现“为每个 Chunk 生成独立上下文描述并同时重建向量 / BM25 索引”的完整 Contextual Retrieval。只有建立上下文依赖错误集、重建双索引并完成 A/B 后才能写成已完成。

### 4. 商品库正式检索评测

数据和运行链路已具备，但尚缺商品事实、别名、规格比较、兼容性、组合筛选和领域外问题的人工 Gold。下一轮应先用 10 题跑通，再扩展到 50～80 题。

## 五、下一步优先级

1. P0：建立商品库 10 题最小 Gold，跑通路由与检索导出；
2. P0：扩到 50～80 题，计算路由准确率、Hit@5、MRR@10、Recall@20、Top5 无关结果与 P95；
3. P1：备份并重建历史乱码批次；
4. P1：为 `RetrievedChunk` 增加来源、逻辑键和分数类型，之后再做证据门控 / 引用；
5. P2：只在上下文依赖错误集证明确有必要时，实施 Contextual Retrieval A/B。
