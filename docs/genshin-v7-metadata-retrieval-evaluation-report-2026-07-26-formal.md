# 原神 v7 元数据检索 A/B 测试报告（56 题正式集）

## 结论

在相同 v7 语料、相同意图结果、相同 ES / Milvus / Rerank 链路下，仅打开
`element` 元数据条件后，元素集合题显著变准，而单实体检索没有发生 Recall@20 漏召回。

| 指标 | Baseline：关闭 `element` | Candidate：开启 `element` | 变化 |
| --- | ---: | ---: | ---: |
| 单实体 / 别名题 Hit@5 | 97.73% | 97.73% | 0 |
| 单实体 / 别名题 MRR@10 | 0.9571 | 0.9571 | 0 |
| 单实体 / 别名题 Recall@20 | 100.00% | 100.00% | 0 |
| 七道元素集合题实体覆盖率@20 | 24.34% | 100.00% | +75.66 个百分点 |
| 所有计分题 Top5 错误召回率 | 33.90% | 14.41% | -19.49 个百分点 |
| 检索延迟 P50 | 220ms | 212.5ms | -7.5ms |
| 检索延迟 P95 | 585ms | 542ms | -43ms |

可以得出的工程结论是：`element` 与 `category / doc_type` 一起参与计划过滤后，能够防止元素集合问题把候选池浪费在其他元素角色上；在本轮题集中没有观察到它导致单实体 Gold 漏召回。P95 在本次运行中略低，但样本仍是本地单机批次，不能把这解释成稳定的性能提升承诺。

## 测试口径

- 时间与运行标识：2026-07-26，`formal-20260726-extended-152025`。
- Gold 集：56 题，均已人工确认候选证据；数据文件为 `tests/eval_rag/data/genshin_v7_metadata_gold.extended.jsonl`。
- 计分构成：44 道单实体/别名题、7 道元素集合题、5 道无实体或领域外诊断题。
- 执行方式：预热 3 次；每题重复 5 次。Baseline 和 Candidate 各保存 280 条请求记录，其中每条策略各有 255 条计分记录（220 条 Chunk 指标、35 条集合覆盖指标）和 25 条诊断记录。
- 对照方式：一次请求先完成一次意图识别与实体解析；两条分支复用这份结果，只改变 `elementFacetEnabled`。这避免把模型分类波动误归因给 `element` 条件。
- 评价范围：检索 Top20；不评价最终 LLM 回复的文风、引用质量或事实组织。

## 发现的缺口

### 1. “草神”别名未命中纳西妲

`草神的元素战技是什么？` 在两套策略下都没有命中 Top5，Gold Chunk 首次出现在第 9 位。

- 计划中的 `entityResolution.status` 为 `NOT_FOUND`；
- 后续仍能通过“角色技能”范围检索到相关资料，但排序不够靠前；
- 原因是当前实体目录没有把“草神”维护为纳西妲的别名，而非 `element` 过滤造成。

这也是 44 道 Chunk 题中唯一未命中 Hit@5 的题。下一次改造应把别名作为实体目录数据治理的一部分，补齐后单独增加回归测试，而不是通过放宽检索范围掩盖问题。

### 2. 领域外拒答尚未实现

`银狼的技能是什么？` 被识别为角色技能但未找到实体，仍返回原神角色 Chunk；`卡芙卡的技能是什么？` 没有 v7 意图计划，但全局回退仍返回 Chunk。

这两题在本次仅作为诊断，不计入 Hit@5、MRR 或覆盖率。当前项目不能声称已经具备可靠的领域外拒答或证据门控能力。

### 3. 历史导入正文编码问题

少数旧导入行的中文正文是 `?`，但 `entity_id / doc_type / chunk_index` 保持正确。评测端点以正文 SHA-256 为主、唯一元数据三元组为兜底恢复 `logical_chunk_key`；最终正式运行未映射 Chunk 数为 0。

这是测试可追溯性修复，不是对数据乱码的根治。应在独立任务中定位旧导入批次、备份并重建受影响文档，不能为了得到评测数字直接覆盖数据。

## 对简历的影响

> 2026-07-31 后续状态：已用受控别名表补齐“草神 → 纳西妲”并增加回归测试；顶层知识库路由已支持显式 `UNKNOWN`，可阻止领域外问题继续进入受管原神/商品库。由于现有召回分与 Rerank 分的口径尚未统一，检索后证据门控仍未完成，历史编码问题也仍需备份后重建。下述数字仍是 2026-07-26 原始 A/B 结果，不因后续修复而改写。

本轮可以诚实支持“元数据分层混合检索”的改造故事，但不支持“Contextual Retrieval 已完成”的表述。

更稳妥的项目表述是：

> 针对元素集合问题跨类别候选混杂，补齐角色 `element` 元数据并同步接入 Milvus 与 Elasticsearch 分层过滤；在 56 条人工确认题的离线 A/B 中，元素集合实体覆盖率@20 从 24.34% 提升至 100%，Top5 错误召回率从 33.90% 降至 14.41%，单实体题 Recall@20 保持 100%。

注意：56 条仍是小型离线集，面试时应说明它是项目自建的人工确认测试集，而不是公开基准；同时主动说出已发现的“草神别名”和领域外拒答缺口，会比假装系统无缺陷更可信。
