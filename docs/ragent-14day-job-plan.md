# Ragent 14天求职速成计划（Java有基础，AI零基础）

> 目标：14天内把项目讲清楚、能演示、能写进简历、能应对面试追问。

## 一、学习原则（只抓主干）

1. 每天只做三件事：看主链路、跑验证、写输出。
2. 每天必须有可交付产物（图/笔记/日志/commit）。
3. 讲不清就不算学会：每天最后3分钟口述录音。
4. 先掌握工程化AI能力，再补算法细节。

## 二、项目地图（先背下来）

- 聊天主入口：`/rag/v3/chat`（SSE）
- 主流程：重写 -> 意图 -> 检索 -> 组Prompt -> 模型路由 -> 流式返回
- 后端模块：`bootstrap`（业务）、`framework`（通用）、`infra-ai`（模型层）、`mcp-server`（工具服务）
- 前端重点：`chatStore` + `useStreamResponse`（事件流处理）
- 配置关键：`bootstrap/src/main/resources/application.yaml`

## 三、14天主线计划（每天约3小时）

### Day 1：跑通与画全链路

- 目标：能完整描述“用户发问到返回答案”的路径。
- 必做：
1. 启动前后端，完成登录。
2. 画一张链路图（前端 -> 后端 -> AI -> SSE回传）。
3. 记录一次真实日志（成功/失败都可以）。
- 产物：`day1-链路图.png` + `day1-运行记录.md`

### Day 2：吃透聊天主流程

- 目标：能逐步解释 `RAGChatServiceImpl`。
- 必做：
1. 标注每一步输入输出（history、rewriteResult、subIntents、ctx）。
2. 写出“为什么要先重写和意图识别”。
- 产物：`day2-主流程拆解.md`

### Day 3：问题重写与意图识别

- 目标：理解“为什么要把一个问题拆成多个子问题”。
- 必做：
1. 阅读 rewrite + intent 相关代码。
2. 自造5个问题，写出预期重写与意图分类。
- 产物：`day3-重写与意图样例.md`

### Day 4：多通道检索与后处理

- 目标：能解释“召回-去重-重排”的价值。
- 必做：
1. 阅读 `RetrievalEngine` 和 `MultiChannelRetrievalEngine`。
2. 明确两类通道的触发逻辑与结果合并方式。
- 产物：`day4-检索链路说明.md`

### Day 5：模型路由与降级容错

- 目标：能解释“多模型fallback”如何保障可用性。
- 必做：
1. 阅读 `RoutingLLMService` + `ModelRoutingExecutor`。
2. 用你当前“密钥缺失/Ollama未启动”的日志写一次故障复盘。
- 产物：`day5-模型降级复盘.md`

### Day 6：会话记忆与摘要压缩

- 目标：能讲清“为什么不用把全部历史都喂给模型”。
- 必做：
1. 阅读 memory 相关实现。
2. 总结“短上下文 + 摘要”的成本收益。
- 产物：`day6-记忆机制笔记.md`

### Day 7：并发、限流、队列

- 目标：能从工程角度说明系统稳定性设计。
- 必做：
1. 阅读 `ThreadPoolExecutorConfig` 与 `ChatQueueLimiter`。
2. 写出“高并发下如何防止打爆模型调用”。
- 产物：`day7-并发与限流.md`

### Day 8：数据库与业务模型

- 目标：能说清核心表和关系。
- 必做：
1. 阅读 `schema_table.sql`。
2. 重点梳理会话、消息、知识库、trace、入库任务五类表。
- 产物：`day8-数据模型图.md`

### Day 9：知识库入库流水线

- 目标：能讲清 ingest 从“源”到“向量”的处理。
- 必做：
1. 阅读 `IngestionEngine` + 节点接口与实现。
2. 自测一次文件上传入库流程。
- 产物：`day9-入库流水线.md`

### Day 10：MCP工具机制

- 目标：能解释 MCP 的作用和调用过程。
- 必做：
1. 阅读 `mcp-server` 的 endpoint + dispatcher。
2. 跑通至少一个工具调用（如天气）。
- 产物：`day10-MCP调用说明.md`

### Day 11：前端SSE与状态管理

- 目标：能讲清前端如何消费流式事件。
- 必做：
1. 阅读 `useStreamResponse.ts` + `chatStore.ts`。
2. 整理事件流：meta/message/finish/done/error。
- 产物：`day11-前端流式处理.md`

### Day 12：做一个小改动并提交

- 目标：形成“可证明贡献”。
- 必做：
1. 选一个小需求（日志增强、错误提示优化、小bug修复）。
2. 提交1个清晰commit。
- 产物：`commit记录 + 改动说明`

### Day 13：简历项目包装

- 目标：写出可投递版本。
- 必做：
1. 完成“项目简介 + 技术难点 + 结果”三段式。
2. 每段都要有可追问的代码锚点。
- 产物：`day13-简历项目描述.md`

### Day 14：模拟面试与查漏补缺

- 目标：达到“可口述、可追问、可落地”。
- 必做：
1. 自问自答20题（至少10题围绕主链路）。
2. 复盘卡壳点并回看源码。
- 产物：`day14-面试问答清单.md`

## 四、每天固定时间模板（3小时）

1. 90分钟：只看当天主模块源码。
2. 60分钟：跑接口/看日志/断点验证。
3. 30分钟：写产物并录3分钟口述。
